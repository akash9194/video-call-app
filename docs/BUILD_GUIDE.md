# Video Calling Feature — Setup, Build & Store Deployment Guide

This covers two things: (1) getting the video call feature running locally, and (2) turning the React Native app into installable iOS/Android apps and publishing them.

## 0. What you have

- `backend/` — FastAPI + MongoDB signaling server (auth, user list, WebSocket signaling for call setup)
- `mobile/src/` and `mobile/App.tsx` — the React Native screens/logic for the video call feature
- `mobile/package.json` — the dependencies this feature needs

`mobile/` currently has source code but **not** the native `android/` and `ios/` folders. Those are large, platform-specific, and best generated by the React Native CLI itself rather than hand-written — step 2 below generates them and you drop the provided source into place.

---

## 1. Run the backend

```bash
cd backend
python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env          # edit JWT_SECRET_KEY at minimum
```

Start MongoDB (local install, or `docker run -d -p 27017:27017 mongo`), then:

```bash
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

Check `http://localhost:8000/health` returns `{"status":"ok"}`. Interactive API docs are at `http://localhost:8000/docs`.

---

## 2. Create the React Native project shell

We didn't hand-write `android/`/`ios/` because they must match your exact React Native/Xcode/Gradle versions. Generate them, then merge in the provided code:

```bash
npx @react-native-community/cli init FreelanceVideoCallApp --version 0.74.3
```

Then, from the generated `FreelanceVideoCallApp/` folder:
1. Delete the generated `App.tsx` and copy in this repo's `mobile/App.tsx` and `mobile/src/`.
2. Merge this repo's `mobile/package.json` dependencies into the generated `package.json` (keep the generated `scripts`/native-related entries as-is, just add the new deps listed).
3. Copy `babel.config.js` and `tsconfig.json` over (or merge if the generated ones differ).
4. `npm install`

## 3. Android native setup

**Permissions** — add to `android/app/src/main/AndroidManifest.xml`, inside `<manifest>` (above `<application>`):

```xml
<uses-permission android:name="android.permission.CAMERA" />
<uses-permission android:name="android.permission.RECORD_AUDIO" />
<uses-permission android:name="android.permission.MODIFY_AUDIO_SETTINGS" />
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.ACCESS_NETWORK_STATE" />
<uses-permission android:name="android.permission.BLUETOOTH" android:maxSdkVersion="30" />
<uses-feature android:name="android.hardware.camera" android:required="true" />
<uses-feature android:name="android.hardware.camera.autofocus" android:required="false" />
```

`react-native-webrtc` auto-links via React Native's native module autolinking — no manual `MainApplication` edits needed on RN ≥ 0.60.

**Minimum SDK**: `react-native-webrtc` requires `minSdkVersion 24+`. Check `android/build.gradle` and bump if lower.

**Run it:**
```bash
npx react-native run-android
```
On a physical Android device, plug in via USB with USB debugging on, or use `adb connect <device-ip>:5555` for wireless.

## 4. iOS native setup

Requires a Mac with Xcode installed (Apple doesn't allow building/signing iOS apps elsewhere).

```bash
cd ios
pod install
cd ..
```

**Permissions** — add to `ios/FreelanceVideoCallApp/Info.plist`:

```xml
<key>NSCameraUsageDescription</key>
<string>We need camera access so you can make video calls.</string>
<key>NSMicrophoneUsageDescription</key>
<string>We need microphone access so you can make voice/video calls.</string>
```

**Background audio (optional, lets a call keep audio if the app is backgrounded)** — add to Info.plist:
```xml
<key>UIBackgroundModes</key>
<array>
  <string>audio</string>
  <string>voip</string>
</array>
```

**Run it:**
```bash
npx react-native run-ios
# or open ios/FreelanceVideoCallApp.xcworkspace in Xcode and hit Run
```
`react-native-webrtc` needs a real device or the iOS Simulator (camera won't work in Simulator — use a physical iPhone to actually test video).

## 5. Point the app at your backend

`mobile/src/config.ts` has `API_BASE_URL`/`WS_BASE_URL`. For local testing:
- Android emulator: `10.0.2.2` (already set) reaches your machine's `localhost`.
- iOS simulator: `localhost` works directly.
- Physical device (either OS): use your computer's LAN IP, e.g. `http://192.168.1.20:8000`, and make sure the phone is on the same Wi-Fi and your firewall allows port 8000.

For production, replace with your deployed backend's HTTPS/WSS URL — plain `http://`/`ws://` won't be allowed by iOS App Transport Security or by Android's cleartext-traffic restrictions on release builds.

## 6. TURN server — required before you ship

STUN alone (the default `stun.l.google.com` in `.env.example`) works for calls where both people happen to be on networks with permissive NAT. On real mobile networks/corporate Wi-Fi, a meaningful percentage of calls will fail to connect without a **TURN** relay.

Cheapest path: run [coturn](https://github.com/coturn/coturn) on a small VPS.

```bash
sudo apt install coturn
# /etc/turnserver.conf — minimum viable config:
listening-port=3478
fingerprint
lt-cred-mech
user=myuser:mypassword
realm=yourdomain.com
```

Then set in `backend/.env`:
```
TURN_URL=turn:yourdomain.com:3478
TURN_USERNAME=myuser
TURN_CREDENTIAL=mypassword
```
The `/calls/ice-servers` endpoint picks this up automatically and the app fetches it before every call. For production, rotate TURN credentials (short-lived, HMAC-based) rather than a static user/pass — coturn supports this via its REST API mode.

## 7. Building & shipping to the Play Store (Android)

1. **Generate a signing key** (once, keep it safe forever — losing it means you can never update the app again):
   ```bash
   keytool -genkeypair -v -storetype PKCS12 -keystore release.keystore -alias release-key -keyalg RSA -keysize 2048 -validity 10000
   ```
2. Place `release.keystore` in `android/app/`, and add to `android/gradle.properties`:
   ```
   MYAPP_RELEASE_STORE_FILE=release.keystore
   MYAPP_RELEASE_KEY_ALIAS=release-key
   MYAPP_RELEASE_STORE_PASSWORD=your-password
   MYAPP_RELEASE_KEY_PASSWORD=your-password
   ```
3. In `android/app/build.gradle`, wire up the `signingConfigs.release` block to those properties (the RN template already has a commented-out example — uncomment and point it at the vars above).
4. Build the release bundle:
   ```bash
   cd android
   ./gradlew bundleRelease
   ```
   Output: `android/app/build/outputs/bundle/release/app-release.aab`
5. Create a [Google Play Console](https://play.google.com/console) account ($25 one-time fee), create an app, fill in the store listing (screenshots, description, privacy policy — required since you request camera/mic), and upload the `.aab` under Production (or Internal Testing first, which is recommended).
6. Since the app requests camera/microphone, Google will ask you to complete a **Data Safety** form and, if targeting sensitive permissions, may request a short justification/demo video during review.

## 8. Building & shipping to the App Store (iOS)

1. Enroll in the [Apple Developer Program](https://developer.apple.com/programs/) ($99/year).
2. In Xcode, open `ios/FreelanceVideoCallApp.xcworkspace`, select your team under Signing & Capabilities, and let Xcode manage signing (simplest) or set up manual provisioning profiles.
3. Set a unique Bundle Identifier (e.g. `com.yourcompany.freelancevideocall`).
4. `Product > Archive` in Xcode, then use the Organizer window to upload to App Store Connect (or `xcodebuild -archive` + `xcodebuild -exportArchive` for CI).
5. In [App Store Connect](https://appstoreconnect.apple.com), create the app record, fill in the listing, and submit the build for review. Apple review pays close attention to apps requesting camera/mic — have a working test account ready in case reviewers need to actually place a call.
6. Consider TestFlight first to get real-device testing across iOS versions before a public submission.

## 9. Common gotchas

- **Video call works on emulator/simulator but not real device**: almost always a networking issue — the device can't reach your backend's host/IP. Use your LAN IP or a deployed HTTPS backend, not `localhost`.
- **Calls connect on Wi-Fi but fail on cellular**: you need TURN (step 6) — cellular NATs are usually symmetric and block direct P2P.
- **Black remote video / no audio**: check that `pc.ontrack` in `CallContext.tsx` fires and that ICE candidates are actually being exchanged both ways — add temporary `console.log`s in `signaling.ts` to confirm both `webrtc:offer`→`webrtc:answer`→`webrtc:ice-candidate` all flow.
- **iOS build fails on `pod install`**: make sure CocoaPods is installed (`sudo gem install cocoapods`) and you're on a Mac; there is no way around this requirement.
- **Play Store rejects app for permissions**: fill in the Data Safety section accurately and make sure your privacy policy URL (required) actually describes camera/mic/call data usage.
